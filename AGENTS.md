# AGENTS.md

- **No backward-compatibility bloat**: Remove legacy code paths rather than maintaining compatibility layers, fallbacks, or migrations.
- **Check existing dependencies first**: Read existing dependencies' docs and type definitions before implementing functionality yourself or adding a new dependency.
- **Avoid defensive over-engineering**: Do not add arbitrary cryptographic hashes, intra-process attestation chains, or redundant validation gates unless you can name the concrete failure they prevent and why standard mechanisms are insufficient.
- **Laziness Protocol (Minimal Change & Negative Delta)**: Bias toward deletion and the simplest native fix at the owning layer (e.g., database timeout or engine tick loop) rather than adding wrapper layers, premature abstractions, or retry middleware.
- **Stop & Ask**: When an assumption fails twice against real execution, a gate conflicts with a requirement, or an irreversible/destructive action is needed, stop and report the blocker with evidence instead of guessing or inventing workarounds.
- **Workspace & Code Hygiene**: Keep temporary exploratory scripts in `scratch/` or `.tmp/`, never in the repo root. Before completion, run `/no-comments` to remove AI narration comments, dead commented-out code, and suppression directives (`@ts-ignore`, `eslint-disable`).
- **Verification Entry Points**: `pnpm prelive` (`node tools/prelive.mjs --no-game`), `pnpm typecheck`, `pnpm test`, `pnpm lint`. Check `package.json` or CI workflows before calling any failure red.
- **Workflow Playbooks**:
  - *General Engineering*: Use TDD (reproducible red check → minimal native fix → green verify) for bug fixes, and strict zero-behavior-change passes for refactoring.
  - *Multi-agent Delegation*: Use `subagent-driven-development` for sliced parallel execution and progressive gate review.
  - *Subdomain Guides*: Follow nested `AGENTS.md` when working inside a domain (`integrations/stardew/AGENTS.md` for Mod & game actions; `tools/live-run/AGENTS.md` for live runs & action slices).
- **Attribution Discipline (evidence against your hypothesis, not for it)**: Collect all facts—including those that refute your hypothesis—before explaining an unexpected run. A missing tool call may be a refused call, so always count *refusals* beside *calls*. When an agent's own account is available, consult it first (`design/handbook/live-attribution.md`) and verify it against the artifacts.
- **Change Discipline** (executable version: `design/operations/change-discipline.md`):
  - *One unit, one commit, the moment it is green*: use an explicit pathspec and verify the hook's printed staged set. Never `restore`/`checkout --`/`stash`/`clean` another lane's uncommitted work; isolate your commit via a private index if needed.
  - *A unit is finished when `HEAD` contains it*: `git cat-file -e HEAD:<path>` succeeds and `git diff HEAD -- <path>` is empty for every changed path. If a hook blocks the commit, name the hook and its output.
  - *Align the shared index after a private-index commit*: `GIT_INDEX_FILE` + `read-tree HEAD` leaves the shared index on pre-commit blobs; before committing, verify `HEAD` has not moved on your target paths (or rebuild from the latest `HEAD`) so you do not revert a concurrent lane's commit, then run `git restore --staged -- <your paths>` and verify `git status --porcelain -- <your paths>` is empty.
  - *Confirm the revision before comparing*: check `git show <rev>:<path>` or `git diff --stat <rev> -- <path>`; a clean worktree is not evidence of which revision you are on.
  - *Key comparison identities on content, not position or form*: never key hashes, baselines, or dedupe IDs on line numbers, list positions, or reflected member order; mark any ceiling reading as a ceiling.
  - *Run CI's authoritative command before calling it red*: check `package.json` or the workflow step first (e.g., `.ts`-importing tests, scoped linter paths, `git archive` vs CRLF worktree).
  - *Fit each lane's task in one transmission*: land the red gate first, then commit one unit at a time.
  - *Every new assertion must be seen red once* on a real violation (or historical pre-fix commit).
  - *Diagnose by executing, not by reading*: call the real function with real inputs from the deciding layer outward; a diagnostic that re-implements predicate logic can disagree with the real shape check.
  - *Verify a check's boundary*: confirm what a gate actually loads and parses before trusting a green pass.
  - *Fix the owning layer, not the call site*: fix the single mapper or producer rather than patching downstream callers or adding strippers.
  - *Destructive actions carry no unforeseen side effects*: if a state leaves data unreachable, fix reachability rather than deleting to tidy up.
  - *Pair every "unchanged" claim with both readings from the same run* and state what was not verified.
  - *Start from existing gauntlets* (`gates/meta/audit-totality.mjs`) instead of inventing another.
- **Defect Families & Invariant Gates**: On meeting **any** defect, name its class and write the red gate first—the gate is the deliverable, the fix is the side effect. Tests must assert durable invariants, not transient implementations:
  - *Zero forward path*: Every reachable non-terminal state in a lifecycle or state machine must offer at least one valid forward action.
  - *First-viewport reachability*: Primary action controls must remain fully visible within the baseline viewport (including mobile 400x800) without requiring container scroll.
  - *End-to-end data consumption*: Any configuration or card field accepted and stored for runtime use must be asserted to reach the assembled prompt or execution pipeline.
  - *Draft preservation*: User input must never be discarded on API, validation, or network failures; verify text retention across all failure shapes.
  - *Lossless round-trip*: Exporting imported structures must preserve all accepted fields and metadata without silent loss or mutation.
  - *Surface protocol isolation*: Surface-specific instructions and tool bindings must remain strictly isolated to their target runtime, verified by negative assertions on other surfaces.
  - *Bounded collections have a drain*: Anything appended during a run has either an eviction path or a derived population bound; test when drain is slower than fill.
  - *Observable state*: Every condition the code distinguishes but cannot prevent has a named field or event a caller can act on.
  - *Single authority per fact*: No fact gets two spellings; derive from the union/descriptor/constant and validate cross-boundary values against the producer's real output.
  - *Mutable config never vetoes durable history*: A mutable profile or preference may trigger reconciliation or change detection, never block reading already-persisted state.
  - *Resource lifetime & clean measurement*: Drain before close, release handles on error paths, and key handles on the resource's identity rather than the transient worker/process; grade end-state rather than intermediate steps, and never let measurement perturb what it measures.
- **Gate Selection** (choose the gate by the layer that owns the fact, never by which language is convenient):
  - *Cross-process or cross-language protocol* → ONE black-box conformance suite driving the real binary (process + pipe + NDJSON + exit code) via production encoders, asserting named codes and diagnostic fields.
  - *Shared vocabulary or shape* → one language-neutral contract or runtime manifest with generated, regeneration-gated consumers; never hand-copied mirrors or cross-language regex scraping.
  - *Compiler-expressible invariant* → the compiler (`IDisposable`/`using`, `#[must_use]`, exhaustive `switch`, `TreatWarningsAsErrors`, exhaustive key maps); do not duplicate compiler guarantees in scripts.
  - *Reachability, policy, or cross-process agreement* → a gate whose population is derived from the authority, printed, and blocked at zero.
  - *Reading source text* → allowed ONLY for declarations (union, descriptor, constant) or unchangeable third-party code. Every such gate must declare `// source-invariant:` and `// source-expiry:` and track any debt in a baseline.
- **Test Design**:
  - *Right-BICEP*: Right results, Boundary conditions, Inverse relationships, Cross-checks, Error conditions, Performance budgets.
  - *CORRECT boundaries*: Conformance, Ordering, Range, Reference, Existence, Cardinality, Time.
  - *A TRIP*: Automatic, Thorough, Repeatable, Independent, Professional (named for the property it protects, with actionable failure messages).
  - *Test doubles*: Mock only boundaries you do not own (network, clock, filesystem, external processes)—never the unit under test or its collaborators; construct fixtures through the producer's real schema or factory rather than hand-written partial projections, and drive cross-component tests from the producer's real output.
- **Gates vs. Tests**: A test pins known behaviour; a gate catches an entire defect class for future, unwritten members and must outlive today's tree:
  - *Population from authority*: Derive the checked set from a union, route table, descriptor, directory scan, or generated artifact—never a hand-maintained list.
  - *Assert a property, not a member*: Check general invariants rather than enumerating current exceptions.
  - *Name the drifting member*: Failure messages must identify the exact action, family, or field that drifted and what must change.
  - *Prove it red on real history*: Replay the pre-fix commit where possible (or state explicitly if no historical defect exists before using a synthetic injection).
  - *Fix the shape, not the allow-list*: A growing exception list signals a structural flaw.
  - *Print the population and distinguish the three zeroes*: Always log `examined N`; distinguish `not_measured` (missing prerequisite), blocked zero (defect), and genuine zero (`allowEmpty: "<reason>"`).
  - *Judge from parsed output, not child exit code*: Strip transport noise (control sequences, lone `\r`) and block if a child exits 0 without readable output.
  - *Expiring exemptions and live wiring*: Allow-list entries must fail once their target disappears, and every gate must be wired into the automated entry point.
- **Rule Lifecycle**: When a rule becomes deterministically enforced by a compiler, hook, or gate, delete its prose from `AGENTS.md`.
