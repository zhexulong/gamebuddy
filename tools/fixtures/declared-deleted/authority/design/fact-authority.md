# Fact Authority

> 一条事实是什么、由谁拥有、什么时候变成一个回合 —— 这份文档是唯一权威。
> 违反它的代码形状，由 `tools/check-fact-authority.mjs` 判红。

## 1 · 一条事实的定义

**事实 = 世界的变化，或一个决定。** 而**身体的痕迹不是事实。**

| 是事实 | 不是事实 |
|---|---|
| 一格被锄了 · 一件被收了 · 一个物品进了包 | **走了一格** |
| 一次拒绝（带理由码） | **身体空闲了** |
| 一个程序结算（成功/失败） | **执行开始了** |
| 玩家说话 · 她到达一个地方 | **工具被装上了**（属于结算的证据） |
| NPC 说话 · 一个提示弹出 | "正在做第 N 项" |

判据一句话：**去掉这条记录，玩家会损失信息吗？** 若不会，它是过程，不是事实。

## 1b · 对齐 Pi：模型看到的东西只有三类

Pi 的模型里没有"事件流"。模型看到的全部内容就是：系统提示、历史、**它自己那次工具调用的结果**、玩家说的话。
它需要世界信息时**自己调用工具去问**。

**所以一条世界事实被交付，只可能是四种情形之一：**

```
① 模型自己问了（`stardew_observe`）—— 这是 pull，不是 push
② 它是模型自己那次调用的**结果**（一次结算，成功或失败）
③ 它是一个**决定**，模型必须看见才知道自己该改（一次拒绝，带理由码）
④ 玩家说话了
```

**除此之外，什么也不该交付。** 世界变化但模型没问、也不是它自己动作的结果 ⇒ **沉默**。

推论（每一条都可判红）：

- **`<world-facts>` 的"世界变了"推送不需要存在。** 她想知道，就调用 `observe`。
- **`<in-flight>` 的逐行进度不需要存在。** 她的程序在跑，她会在结算时看到结果。
- **`route_progress` / `tile_advanced` / `body_idle` / `execution_started` 不需要存在。** 它们既非结果也非决定。
- **留下的只有三类**：**工具结果**（含拒绝）· **玩家输入** · **到达**（一个新世界开始，她还没有任何历史）。

⇒ 这与 Pi 的 `edit` 完全同构：你调用 `edit`，拿到一个结果；文件在系统里怎么变化的过程，你从来不需要知道。

## 1c · 回执自己的权威

**回执不是"世界事实"，回执是"你那次调用结束了，结果是这样"。** 它有自己唯一的权威：**执行者**。

```
回执的权威 = 执行者（Mod）—— 它拥有"这次执行结束了、结果是这样"
回执的形状 = 协议的一份声明（programId · nodeId · outcome · evidence · postcondition）
回执的投递 = **模型历史里，作为它自己那次调用的结果**（就同为 Pi 的 tool result）
```

**而现在的链条是三层改名：**

```
Mod 发回执  →  `toWorldFact`（stardew-integration-launcher-body-program.internal.ts）把"结果"改名为"世界事实"
           →  泵再判断这条"事实"该不该开回合
           →  装配器再把它渲染成 `<world-facts>` 里的一行
```

⇒ **三个权威各自对"这次执行是什么"给出了自己的答案。** 而 round64 的结果是：401 条"事实"、
134 次冲刷、132 条被丢、而真正的回执（程序结算）只有 22 条。

**所以：回执不进"世界事实"那个词汇表。**

- **回执走工具结果那条路**，原样（有界）进历史。
- **`toWorldFact` 对回执的改名应删除**；它对快照仍然有用（快照确实是一个境界面）。
- **一条回执不竞争回合**：它属于**已经发生**的那次调用，它作为结果到达，不需要“开一个新的回合”。

⇒ 而判据是同一个：**同一件事只许有一个权威。** 一次执行的结果由执行者说，不由它下游的三个模块各说一遍。

## 2 · 一次调用的答案只有一个

**形状照工具结果，不照日志。** 一次调用 → 一个结果：

```
{ ok: true,  summary: "锄 57 格 · 3 格被挡", refused: [{ tile, reason }] }
{ ok: false, reason: "sweep_needs_cardinal_stance", detail: "…" }
```

- **一个程序最多一条结算回执**，不是每节点一条。
- **证据有界且被计数**：60 行就印 12 行 + `其余 48`，**不许静默截断，也不许无界**。
- 失败必须带**理由码**，且该码**点名一个存在的动作或状态**（见 `check-refusal-action-names`）。

## 3 · 四个所有者的分工（同一条主张只写一处）

```
执行器（Mod）      拥有「发生了什么」 —— 按结果，不按步
泵（Host）         拥有「此刻该不该叫醒她」 —— 一次 / 回合，不是 一条 / 次
装配器（Host）     拥有「这一次交付她需要知道哪些」 —— 投影，不是第二个事实源
投递（Host）       拥有「到了，或具名丢了」 —— 不是 lease 的有无
```

**推论三条，都是可判红的：**

1. **`tile_advanced` / `route_progress` / `body_idle` / `execution_started` 不得成为候选事实。**
   它们是身体状态。它们可以在下一个回合的块里作为一行出现一次，或根本不出现。
2. **"有程序在飞"不是一条事实的 suppressor**，是对**轮次**的判断。用它逐条过滤 401 条事实，
   会让 93% 的泵工作变成"组装然后丢弃"。
3. **一条不能开回合的事实，从一开始就不该成为一次待交付批次。**
   若发生了，那是缺陷，不是"被抑制"。

## 4 · 运行的形状

```
type FlushOutcome =
  | { kind: "opened"; turn: Turn }
  | { kind: "not_owed"; reason: "progress_in_flight" | "nothing_pending"; carriedInto: BatchId };
```

- **没有 `undefined`** ⇒ "组装了一批然后什么都没发生"在类型上不可能。
- `carriedInto: BatchId` 是事实**没有消失**的证明。
- 具名拒绝指的就是这个字段：**调用者必须 switch 它**，而不是读一条日志。

## 5 · 判红的门（缺一不可，各自在今天的树上红过）

```
`progress_reported_as_a_fact:<kind>`        人口 = Mod 与 Host 能发出的每一种事实种类（从 wire 的事件联合与
                                            Mod 的 transition 名派生），性质 = 是事件而不是身体痕迹。
                                            打印 `kinds examined N · events E · traces T`；T>0 失败并点名 file:line
                                            ⇒ 今天点名 `tile_advanced`（StardewBodyController.cs:1156）与
                                              `route_progress`
`settlement_is_one_answer_with_a_bounded_evidence:<program>`
                                            人口 = 每个已结算程序，性质 = 恰好一条回执 + 有界且被计数的证据
`fact_flushed_then_discarded:<suppressor>`   人口 = 每一次待交付批次，性质 = 开回合或具名拒绝（带 carriedInto）
                                            打印 `flushes examined N · opened O · named-refused R · discarded D`；
                                            D>0 失败
`delivered_text_never_arrived:<reason>`      人口 = 每一次呈现提交，性质 = 到达或被计为 lost
`progress_kinds_declared_only_in_a_test:<kind>`
                                            人口 = 生产代码里的 progress 概念，性质 = 它不在测试文件里定义
                                            ⇒ 今天 `PROGRESS_KINDS` 只存在于
                                              `host/src/event-pump.held-progress.test.ts:21`
```

## 6 · 为什么要有这份文档

2026-11-16 的 round64：**401 条事实里 260 条是"走了一格"，同一次移动两种拼写**；
泵组装 134 批、丢弃 126 批，只开 8 个回合；而玩家看到的 7 个气泡里有 1 个被扣下且无人告知。

**没有一个模块做错了它自己的事。** 错的是**没有一个权威说"这不算事实"**，于是四个模块各自给了答案，
而它们不一致。这份文档就是那个权威；门是它的执法。
